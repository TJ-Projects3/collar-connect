# Branded Link Previews for NextGen Collar

Make shared links show a clean, branded card on LinkedIn, X/Twitter, iMessage, Slack, and WhatsApp, using the official address `https://nextgencollar.lovable.app` instead of the old preview address.

## What changes

1. **Correct address everywhere**
   - Every place in the page's sharing info that currently points at `preview--collar-connect.lovable.app` switches to `https://nextgencollar.lovable.app`.
   - Add a canonical link so search engines treat the official address as the real one.

2. **Consistent title and description**
   - Keep the existing title: "NextGen Collar - Elevating Rising Talent To Build The Next Generation".
   - Keep the existing description and mirror it into the Twitter-specific description tag, which is currently missing, so X shows text rather than falling back.
   - Add the missing `og:site_name` ("NextGen Collar") and `twitter:title`.

3. **Properly sized preview image**
   - The current preview image is the 900x630-square app icon, which social platforms crop awkwardly.
   - Create a 1200x630 share card from the existing stacked NextGen Collar logo (`NextGenCollar_main_stacked.png`) — the logo centered on the brand navy background, saved as a new file in `public/`.
   - Point both the Open Graph and Twitter image tags at that file at the official address, and add image width/height plus alt text so platforms render it immediately without re-measuring.

4. **Publish note**
   - Link previews read the last published version of the site, so these changes only reach LinkedIn, X, and iMessage after the next publish. Platforms also cache previews they have already fetched, so an old card can linger until they re-check or you force a refresh in a link preview debugger.

## Technical details

- File touched: `index.html` (head tags only).
- New asset: `public/nextgencollar-share-card.png`, 1200x630, generated by compositing the existing stacked logo onto a solid `hsl(203 60% 26%)` navy canvas with `magick` — no new artwork invented.
- Tags after the change: `title`, `description`, `author`, `link rel=canonical`, `og:site_name`, `og:title`, `og:description`, `og:type`, `og:url`, `og:image` (+ `og:image:width`, `og:image:height`, `og:image:alt`), `twitter:card=summary_large_image`, `twitter:site`, `twitter:title`, `twitter:description`, `twitter:image`.
- No route-level metadata is added; this stack serves one static head, so a single accurate app-level card is the target.
